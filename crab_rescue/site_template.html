A room is on fire.
A figurine is inside.
A crab robot has to bring it out.

No human in the loop. A vision-language model looks at camera frames, a language model plans waypoints as strict JSON, a safety validator checks every plan against walls and fire, and a walking policy's velocity commands carry it out - replanning as the fire spreads.

How it works

The language model never writes code. It returns JSON that must pass a strict schema (waypoints inside the room, speed limits, allowed action names only). An invalid or unsafe plan gets a repair retry with the reason, then a stronger model, then the last valid plan is kept. Success is decided by the simulator's ground truth, never by what a model says.

Limitations, stated plainly

  • The fire is a simulated hazard region (a spreading grid of cells), not fire physics. There is no heat, smoke dynamics or combustion.
  • "Carry" is a simplification. The crab has claws, but this project does not simulate grasping: the figurine is welded in front of the crab when it gets within 0.4 m.
  • The walking is a kinematic stand-in in this build. The robot takes the same velocity commands as the trained locomotion policy (forward, lateral, yaw), but this version integrates them directly with wall collisions. There is no balance model, so "falls" are not measured here.
  • Simulation only. Nothing here ran on hardware. The simulation pauses while a model call is in flight, so model latency does not cost simulated time.
  • Perception uses a clean top-down render of a small grid room, not a camera on the robot, and the baselines (blind, oracle) read ground truth by design.
